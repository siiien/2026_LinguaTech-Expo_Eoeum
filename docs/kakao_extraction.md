# 카카오톡 1:1 대화 추출 파이프라인 정리

작성일: 2026-11-19

---

## 1. 개요: 카톡 추출이 연구에서 맡는 일

카톡 추출 파이프라인은 동의받은 1:1 카카오톡 대화를 **익명화된 대화 조각(D5)** 과 **언어적 특성 통계(D4)** 로 바꾸고, 그중 20%를 P2 평가 기준으로 떼어 둔다. 외부 네트워크를 쓰지 않고 Python 표준 라이브러리만으로 동작한다.

| 쓰임 | 연구 설계 항목 | 결과물 | 쓰이는 조건 |
| --- | --- | --- | --- |
| 블록3 입력 (언어적 특성) | D4 | `d4_train.json`, `block3.txt` | B, C, D, E, ②-1, ②-2 |
| 블록4 검색 후보 (대화 예시) | D5 | `retrieval_pool.jsonl` | C(5개), D(30개), ②-1(30개), ②-2(30개에서 일부 뺌) |
| P2 평가 기준 (입력에 안 넣은 20%) | P2 비교 대상 분리 | `d4_holdout.json` | 모든 조건의 P2 채점 |
| P4 원문 중복 계산 | P4 | 조각마다 `fragment_id` | 블록4를 쓰는 조건 |
| E 추가 학습 데이터 | D5 | 80% 쪽 조각 | E |

- 조건 A는 카톡 데이터를 쓰지 않는다.
- 입력 통계와 P2 채점이 같은 함수(`kakao_features.py`)를 써서 두 쪽의 기준이 어긋나지 않는다.

## 2. 전체 흐름

```
카톡 내보내기 파일 (PC / Android / iOS / Mac)
   │
   │ ── prepare ────────────────────────────────────────────
   │  1. 형식 판별
   │  2. 메시지 단위로 자르기 (여러 줄 메시지 = 1개)
   │  3. 본인 / 상대 구분 (단톡방이면 중단)
   │  4. 미디어 표식 정규화 (<사진>, <이모티콘> …)
   │  5. 익명화 (<본인>, <상대>, <인물N>, <전화번호> …)
   │  6. 민감 flag + 세션 나누기 (60분 넘게 끊기면 새 세션)
   ▼
 익명화된 메시지 + 검토 시트
   │
   │ ── 7. 사람 검토 (include 1/0) ──────────────────────────
   ▼
   │ ── build ──────────────────────────────────────────────
   │  8. 턴 → 조각 (상대 턴 + 본인 턴)
   │  9. 80/20 분리 (세션 단위, 관계별, seed 고정)
   │       ├─ 80% → D4 입력 통계 + D5 검색 후보
   │       └─ 20% → P2 기준 통계 (검색에서 제외)
   │ 10. D4 통계 계산
   │ 11. 블록3 문장 (전체 + 관계별)
   │ 12. 점검 (후보 30개, 공유 채팅방)
   ▼
 summary.csv / fragments / retrieval_pool / d4_*.json / block3*.txt
```

## 3. 추출 원리 (단계별)

원본 파일은 읽기만 한다. 1~6단계(`prepare`)에서 익명화된 메시지를 만들고, 사람 검토(7단계)를 거쳐 8~12단계(`build`)에서 연구용 데이터를 만든다.

### 1단계. 파일 형식 판별

파일 앞부분 줄을 정규식으로 검사해 내보내기 형식을 자동으로 고른다. 인코딩은 UTF-16(BOM 있을 때) → UTF-8 → CP949 순으로 시도한다.

| 형식 | 메시지 줄 모양 | 날짜를 얻는 곳 |
| --- | --- | --- |
| PC (Windows·Mac 앱 txt) | `[김민지] [오후 3:12] 내용` | `--- 2024년 5월 2일 목요일 ---` 구분선 |
| Android txt | `2024년 5월 2일 오후 3:12, 김민지 : 내용` | 각 줄 앞부분 |
| iOS txt | `2024. 5. 2. 오후 3:12, 김민지 : 내용` | 각 줄 앞부분 |
| Mac csv | `Date,User,Message` 열 | Date 열 |

### 2단계. 메시지 단위로 자르기 (파싱)

- 메시지 시작 줄에서 **시각·화자·내용**을 꺼낸다. 오전/오후는 24시간제로 바꾼다 (오전 12시 = 0시).
- 시작 패턴이 아닌 줄은 **앞 메시지에 이어지는 줄**로 붙인다. 그래서 "내일 일정⏎1. 10시 도서관⏎2. 1시 점심"은 메시지 1개(안에 줄바꿈 2개)로 남는다.
- 날짜 구분선, "저장한 날짜", 입장·퇴장 같은 시스템 줄은 메시지에서 빠진다.
- 메시지 경계 = 사용자가 전송을 누른 단위. 이 경계가 끝까지 유지돼야 끊어 보내기·줄 길이 통계가 맞다.

### 3단계. 본인·상대 구분

1. manifest에 `self_name` 또는 `partner_name`이 있으면 그걸 쓴다.
2. 없으면 파일 첫 줄 "**OOO 님과 카카오톡 대화**"의 OOO를 상대로, 나머지 화자를 본인으로 본다.
3. 화자가 3명 이상이면 단톡방으로 보고 멈춘다. 제목 이름과 화자 이름이 다르면(저장된 연락처 이름 ≠ 프로필 이름) 멈추고 `self_name`을 적어 달라고 알려 준다.

### 4단계. 미디어 표식 정규화

내용 없이 형식만 있는 메시지는 표식으로 바꾼다. 표식은 길이 계산에서 빠지고, 빈도 통계(예: 카톡 이모티콘 사용)에만 쓰인다.

| 원문 | 표식 |
| --- | --- |
| 사진 / 사진 3장 | `<사진>` |
| 이모티콘 | `<이모티콘>` |
| 삭제된 메시지입니다. | `<삭제됨>` (턴·통계에서 제외) |
| 동영상 / 음성메시지 / 보이스톡 | `<동영상>` `<음성메시지>` `<통화>` |
| 파일: … / 송금: … / 지도: … | `<파일>` `<송금>` `<위치>` |

"사진 찍자"처럼 문장 안에 있는 단어는 바꾸지 않는다. 메시지 전체가 그 문구일 때만 바꾼다.

### 5단계. 익명화

문장 안의 개인정보를 아래 순서로 태그로 치환한다. 순서가 중요하다: 링크 안 숫자가 전화번호로, 날짜가 계좌번호로 잡히지 않게 하기 위해서다.

1. 링크 → `<링크>`, 이메일 → `<이메일>`
2. 주민번호 → `<주민번호>`, 카드번호 → `<카드번호>`, 전화번호 → `<전화번호>`
3. 계좌번호 → `<계좌번호>`: 하이픈으로 나뉜 숫자 덩어리 중 **숫자가 10개 이상**인 것만 (2024-05-01 같은 날짜는 8개라 남는다)
4. 주소 → `<주소>`: "시/도 + 구/군 + 로/길 + 번지", "OO로 107", "101동 1203호". "버스로 20분"처럼 뒤에 분·개·원 등이 오면 주소로 보지 않는다.
5. 8자리 이상 숫자(학번 등) → `<번호>`
6. 이름 → 본인은 `<본인>`, 상대는 `<상대>`, manifest의 제3자는 `<인물1>`…, 장소는 `<장소>`
    - 카톡 표시 이름에서 변형을 만든다: 한글 3글자 이름이면 성을 뗀 이름도 추가 (박서연 → 박서연, 서연). 이모지는 떼고 비교.
    - 긴 이름부터 치환해서 "서연아 뭐해" → "`<본인>`아 뭐해"처럼 조사·호격은 남는다.
    - `<인물N>` 번호는 참여자 안에서 고정한다.

어미, 줄바꿈, ㅋㅋ·ㅠㅠ, 이모지는 건드리지 않는다 (말투 통계의 재료).

### 6단계. 민감 표시(flag)와 세션 나누기

**flag**: 자동으로 지우지 않고 표시만 한다.

- `민감:분류` — 건강(병원·우울…), 금전(대출·빚…), 종교정치, 성, 가족갈등, 법 키워드. 목록은 `--keywords` 파일로 교체 가능.
- `제3자` — "이름+호칭"이 붙어 나오는 경우 (예: 철수오빠, 김교수님). "우리·학교·회사" 같은 단어는 제외.
- `개인정보:태그` — 이미 치환된 주소·계좌 등이 있었다는 정보용 표시.

**세션**: 메시지 사이가 **60분보다 길게** 끊기면 새 세션(연속 대화 구간)이 시작된다. 세션 ID는 시작 시각으로 만들어(`P01-C01-S202405021512`) 다시 돌려도 바뀌지 않는다. 같은 방을 여러 번 내보낸 경우 (시각, 화자, 내용)이 같은 메시지는 하나만 남긴다.

### 7단계. 사람 검토

- `review/P01_sessions.txt`에서 익명화된 대화를 세션별로 읽는다.
- `review/P01_sessions.csv`의 `include` 열을 1(사용) / 0(제외)으로 정한다. `민감` 또는 `제3자` flag가 있는 세션은 0으로 시작한다.
- prepare를 다시 돌려도 이미 정한 include 값은 유지된다 (`--reset-review`로 초기화).
- 치환되지 않은 별명·학교명·회사명이 보이면 manifest에 추가하고 prepare를 다시 돌린다.

### 8단계. 턴 → 조각 만들기

- **턴** = 같은 사람이 연속으로 보낸 메시지 묶음.
- **조각** = 상대 턴 + 바로 뒤 본인 턴. 본인 턴마다 조각 1개가 생긴다.
- 블록4에 들어갈 형식은 메시지마다 한 줄이다 (메시지 안 줄바꿈은 들여쓰기):

```
상대: <본인>아 조별과제 걔 또 안 왔대
P01: 아 진짜 너무하다
P01: 이번엔 교수님한테 말해야 할 듯
```

검색 후보에서 빠지는 조각 (`exclude_reason`):

| 사유 | 기준 |
| --- | --- |
| holdout | P2용 20% 세션에 속함 |
| no_context | 본인이 먼저 말해서 상대 발화가 없음 (`--allow-no-context`로 포함 가능) |
| media_only | 본인 턴이 표식뿐 (예: `<이모티콘>`만) |
| too_short | 본인 텍스트 2자 미만 |
| too_long | 조각 전체 600자 초과 (프롬프트 분량 관리) |

### 9단계. 80/20 분리

- 분리 단위는 **세션**이다. 메시지 단위로 나누면 바로 앞뒤 말이 입력과 정답에 같이 들어가 P2가 부풀려진다.
- **관계별로 따로** 나눈다 (친구·선배 각각 약 20%). 그래야 P2에서 관계별 높임법을 비교할 수 있다.
- 비율은 세션 개수가 아니라 **본인 텍스트 줄 수** 기준. 목표를 크게 넘기는 세션은 건너뛴다.
- 방식: `random`(기본, seed 42로 고정해 재현 가능) 또는 `chrono`(가장 최근 구간을 holdout).
- 세션이 1개뿐인 관계는 나누지 않고 경고한다.

### 10단계. D4 통계 계산

본인 턴만 모아 train(80%)과 holdout(20%) 각각 계산한다. 전체 + 관계별로 나온다.

| 항목 | 계산 방법 |
| --- | --- |
| 줄 길이 | 표식을 뺀 줄의 글자 수(공백 포함). 평균·중앙값·p25/p75/p90 |
| 끊어 보내기 | 턴당 메시지 수 평균, 2개 이상으로 끊은 턴 비율 |
| 어미 | 줄 끝의 ㅋㅋ·ㅠㅠ·이모지·문장부호를 떼고, 마지막 어절을 구어체 어미 목록과 가장 길게 맞춘다. 받침을 보고 -ㄹ게 / -ㄹ게요 / -ㅂ니다를 구분. 비중 5% 이상인 상위 5개 = "자주 쓰는 어미" |
| 높임법 | 줄 끝이 요·죠·습니다·ㅂ니까, 또는 "네·넵·예" → 존댓말. 나머지 한글 끝 → 반말. ㅋㅋ·ㅇㅇ만 있는 줄은 판단 불가 |
| 감정 표현 | ㅋㅋ·ㅎㅎ / ㅠㅠ / ^^·;; 같은 문자 이모티콘 / 이모지가 들어간 줄 비율, 메시지당 카톡 이모티콘 수 |
| 초성체 | ㅇㅇ·ㄱㄱ·ㅇㅋ 등 (ㅋㅋ·ㅎㅎ 제외) 상위 |
| 특징 단어 | 같은 방 상대보다 2배 이상 자주 쓰는 어절 (3회 이상) |
| 문장부호 습관 | 줄 끝 마침표·물음표·느낌표·물결(~)·말줄임(..) 비율 |

### 11단계. 블록3 문장 만들기

train 통계를 프롬프트에 바로 넣을 수 있는 문장으로 바꾼다. 빈도는 단어로 바꾼다: 2% 미만 "거의 안 씀", 10% 미만 "가끔 씀", 30% 미만 "자주 씀", 그 이상 "매우 자주 씀". 가상 참여자 P01의 실제 출력:

```
메시지 길이: 한 줄 평균 10자(공백 포함), 보통 6~14자
끊어 보내기: 한 번 말할 때 평균 1.7개 메시지로 나눠 보냄
자주 쓰는 어미: -음, -듯, -거든, -ㄹ게, -지
웃음 표현(ㅋㅋ·ㅎㅎ): 가끔 씀 / ㅠㅠ: 거의 안 씀 / 카톡 이모티콘: 가끔 씀 / 이모지: 거의 안 씀
문장 끝 마침표: 거의 안 씀
높임법: 선배에게 존댓말 100%, 친구에게 반말 100%
```

D6 질문의 상대가 선배면 `block3_선배.txt`처럼 관계별 파일을 쓴다.

### 12단계. 점검

- **검색 후보 수**: 30개 미만이면 "조건 D 불가" 경고 (`--pool-target`으로 기준 변경).
- **P2 기준 데이터 양**: holdout 텍스트 줄이 30개 미만이면 "통계 불안정" 경고.
- **공유 채팅방**: 두 참여자가 같은 방을 냈는지 판단 → `shared_rooms.csv`. 시각과 내용(본인·상대 태그는 통일)으로 메시지 지문(해시)을 만들고, 겹치는 비율이 30% 이상이면서 5개 이상 겹치면 같은 방으로 본다. 교차 비교에서 해당 조합을 표시한다.

### 13단계. DB 적재

`kakao/kakao_db.py`가 build 결과를 SQLite(`outputs/kakao/research.db`)로 옮긴다. 화면에서는 4단계의 **DB에 저장** 버튼. 구조는 `kakao/schema.sql`.

```
participant ─┬─ chat ── session ─┬─ message          (포함된 세션만)
             │                   └─ fragment ── fragment_embedding
             ├─ d4_stats (train=입력용 / holdout=P2 기준, 관계별)
             ├─ survey_answer ── survey_item (D1~D3, D4 과제, D6 골드셋)
             └─ generation ─┬─ generation_fragment (블록4에 넣은 조각 → P4)
                            └─ score (P1~P5)
```

- 같은 참여자를 다시 적재하면 채팅·세션·메시지·조각·D4만 새로 쓰고 설문·생성·채점은 유지한다.
- 생성 기록이 참조하는 조각이 있으면 적재를 멈춘다 (실험 뒤 입력 데이터가 바뀌는 것 방지).
- 프롬프트 생성은 `v_model_visible_answers` 뷰만 읽는다 (D6 골드셋 차단). 검색 후보는 `v_retrieval_pool`, 조건별 평균은 `v_condition_means`.
- 저장소에는 가상 샘플로 만든 `kakao/samples/sample.db`만 올린다.

## 4. 핵심 정의

입력 통계와 P2 채점이 같은 정의를 써야 한다.

| 용어 | 정의 |
| --- | --- |
| 메시지 | 전송 1회 |
| 줄 | 메시지를 줄바꿈으로 나눈 것. 평균 길이(공백 포함)의 단위. 표식만 있는 줄은 제외 |
| 턴 | 같은 사람이 연속으로 보낸 메시지 묶음. 끊어 보내기의 단위 |
| 조각 | 상대 턴 + 본인 답장 턴. 메시지 경계 유지 |
| 세션 | 60분 넘게 끊기지 않고 이어진 대화 구간. 80/20 분리의 단위 |
| 표현 유사 (P2) | 줄당 평균 길이 차이 ±30% 이내 + 자주 쓰는 어미 1개 이상 사용 |

## 6. 개인정보 원칙과 한계

### 개인정보 원칙

| 구분 | 대상 |
| --- | --- |
| 외부 API로 보내도 되는 것 | `retrieval_pool.jsonl`의 익명화된 텍스트만 |
| 로컬에만 두는 것 (Git 제외) | `data/kakao/`(원본·실명 manifest), `outputs/`(결과·`prepare_report.md`·실제 DB) |
| 민감 구간 | 자동 삭제하지 않고 표시만. 최종 판단은 참여자·팀이 검토 시트에서 |

### 한계

- 어미·높임법 판정은 형태소 분석기 없는 규칙 방식이다. 파일럿에서 100줄 정도 사람이 확인해 정확도를 보고서에 적는 것을 권장한다.
- 이름 자동 치환은 카톡 표시 이름 기준이다. 본문 별명, 제3자 이름, 학교·회사명은 manifest에 적어야 치환된다.
- 성을 뗀 이름이 일반 단어와 겹치면(예: 지원 → 지원서) 잘못 치환될 수 있다. `prepare_report.md`의 치환 횟수로 확인한다.
- 영어 설정 모바일 내보내기는 지원하지 않는다.
- 실제 모바일 내보내기 1건(메시지 약 13만 개)으로 파싱·처리를 확인했다 (prepare 약 4초, build 약 3초). 실제 PC 내보내기 파일은 아직 확인하지 않았다.

## 7. 결정 사항과 다음 할 일

### 팀이 결정할 것

1. 세션 간격 60분이 적당한가
2. flag 붙은 세션을 기본 제외할 것인가 (현재: 제외)
3. 분리 방식: 무작위(현재) vs 최근 구간
4. 검색 후보가 30개 미만인 참여자가 있으면 조건을 5 vs 15로 조정할 것인가
5. 학습 데이터(E)에 쓸 대화 기준

### 아직 구현 안 된 것

| 작업 | 설명 |
| --- | --- |
| 임베딩 검색 | 질문별 상위 30개 → D, 그중 상위 5개 → C. 현재는 후보 파일까지만 만든다 |
| ②-2 구성 | 30개에서 D3 글자 수만큼 대화를 빼는 단계. 조각별 글자 수는 이미 기록됨 |
| 생성 실행 + P4 계산 | 저장 구조(`generation`, `generation_fragment`, `score`)는 준비됨. 생성 실행과 5어절 이상 연속 겹침 자동 계산은 아직 없음 |

### 바로 할 일

1. 다른 팀원의 실제 카톡 파일(특히 PC 내보내기)로 형식 인식 확인
2. 어미·존댓말 판정 100줄 수기 확인
3. 가상 참여자(S1)가 검색 후보 30개를 넘도록 대화 보강 (현재 샘플: P01 26개, P02 7개)
