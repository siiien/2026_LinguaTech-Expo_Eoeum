# 카카오톡 대화 수집 가이드 (팀원·담당자용)

참여자 여러 명의 카톡 대화를 같은 기준으로 익명화해 DB 하나로 모으는 순서입니다.
원리와 저장 구조는 [kakao_extraction.md](kakao_extraction.md), 도구 사용법은 [kakao/README.md](../kakao/README.md)에 있습니다.

## 한눈에 보기

```
담당자: ID 나눠 주기 · 설정값 공지 · 공유 폴더 준비
   │
   ▼
팀원(각자 자기 컴퓨터): 저장소 받기 → 카톡 내보내기 → 화면 1~4단계 → research.db
   │        원본 대화는 내 컴퓨터 밖으로 나가지 않음
   ▼  (비공개 공유 폴더로 DB 파일만 전달)
담당자: 받은 DB 합치기 → merged.db → 현황 확인
```

| 누가 | 하는 일 | 결과물 |
| --- | --- | --- |
| 담당자 | 참여자 ID 배정, 공통 설정 공지, 공유 폴더 준비 | ID 대응표 (비공개) |
| 팀원 | 자기 카톡을 익명화·검토하고 DB로 저장 | `P0X.db` 1개 |
| 담당자 | DB 합치기, 경고 확인 | `merged.db` |

---

## 0. 지켜야 할 것 (모두)

1. **원본 대화 파일은 절대 보내지 않는다.** 보내는 것은 익명화된 DB 파일(`research.db`) 하나뿐이다.
2. **GitHub에 데이터를 올리지 않는다.** 저장소는 공개다. 아래 폴더는 자동으로 막혀 있지만, 다른 곳에 복사하거나 `git add -f`를 쓰면 올라갈 수 있다.
   - `data/kakao/` (원본, 실명이 든 표)
   - `outputs/` (결과, DB)
3. **DB는 비공개 경로로만 주고받는다.** 팀 공유 드라이브의 권한 제한 폴더 등. 메신저 단체방, 공개 링크는 쓰지 않는다.
4. **ID와 실명의 대응표는 담당자만 가진다.** DB 안에는 실명이 없다.
5. 참여 동의를 받은 대화만 쓴다. 상대방이 있는 대화이므로 연구 설계의 동의 절차를 따른다.

## 1. 담당자: 시작 전 준비

### 1-1. 참여자 ID 배정
사람마다 겹치지 않는 ID를 정해 알려 준다. **다들 기본값 P01로 하면 합칠 때 멈춘다.**

| ID | 담당 팀원 | DB 받음 |
| --- | --- | --- |
| P01 | (이름은 이 표에만) | ☐ |
| P02 | | ☐ |
| P03 | | ☐ |

이 표는 저장소가 아닌 비공개 문서에 둔다.

### 1-2. 공통 설정값 공지
조건 비교가 공정하려면 모두 같은 값이어야 한다. **기본값 그대로 두라고 안내하면 된다.**

| 화면 단계 | 항목 | 값 |
| --- | --- | --- |
| 2단계 | 세션 간격(분) | 60 |
| 4단계 | P2용 비율 | 0.2 |
| 4단계 | 분리 방식 | 무작위(관계별) |
| 4단계 | seed | 42 |
| 4단계 | 검색 후보 목표 | 30 |

### 1-3. 공유 폴더와 마감일
- 비공개 공유 폴더를 만들고, 업로드할 사람만 권한을 준다.
- 파일 이름 규칙: `P0X.db` (예: `P02.db`)
- 마감일을 정한다.

## 2. 팀원: 내 대화로 DB 만들기

### 2-1. 준비 (처음 한 번)
필요한 것: Git, Python 3.9 이상. 다른 설치는 없다.

```powershell
git clone -b feat/kakao-extraction-db https://github.com/siiien/2026_LinguaTech-Expo_Eoeum.git
cd 2026_LinguaTech-Expo_Eoeum
```

> PR이 `develop`에 합쳐진 뒤에는 `-b feat/kakao-extraction-db` 없이 받고 `git switch develop` 하면 된다.
> 이미 받아 둔 사람은 `git pull`로 최신 상태를 받는다.

### 2-2. 카톡 대화 내보내기
대상: 연구에 쓸 **1:1 채팅방** (단체방 제외). 방 하나 = 파일 하나.

- **PC**: 채팅방 → ≡ 메뉴 → 대화 내용 → 대화 내보내기 (txt)
- **모바일**: 채팅방 → ≡ → ⚙ 설정 → 대화 내용 내보내기 → 텍스트만 보내기

받은 파일은 아무 폴더에 두고, 다음 단계 화면에서 올리면 된다.

### 2-3. 화면 띄우기
```powershell
python kakao/kakao_web.py
```
(Mac은 `python3`) 브라우저에서 `http://127.0.0.1:8765`를 연다. 이 화면은 내 컴퓨터에서만 열린다.

> 처음이면 1단계의 **가상 샘플 불러오기**로 끝까지 한 번 연습해 보자. 연습이 끝나면 표에서 샘플 행을 지운다.

### 2-4. 1단계 — 파일 등록
1. 내보낸 파일을 끌어다 놓는다. 카드에 형식, 화자, 기간이 나오면 정상이다.
2. 채팅방 목록 표를 채운다.

| 열 | 적을 것 |
| --- | --- |
| **참여자** | **담당자가 준 내 ID로 바꾼다.** 기본값 P01을 그대로 두지 말 것 |
| 방 | C01, C02 … (자동) |
| **관계** | 친구 / 가족 / 선배 / 후배 / 연인 / 동료. **필수** |
| 본인 이름 | 본인/상대 구분이 틀릴 때만 내 카톡 표시 이름 |
| 제3자 이름 | 대화에 나오는 다른 사람 이름. `;`로 구분 (예: `지수;민호`) → `<인물N>`으로 바뀜 |
| 장소 | 학교, 회사, 동네 이름. `;`로 구분 → `<장소>`로 바뀜 |
| 시작일/종료일 | 일부 기간만 쓸 때 |

3. **저장하고 다음 →** 을 누른다.

### 2-5. 2단계 — 익명화·세션 나누기
1. 세션 간격 60 그대로 두고 **실행**한다.
2. 보고서를 확인한다.
   - 화자의 본인/상대가 맞게 나뉘었는지
   - 이름 치환 횟수가 0이 아닌지

### 2-6. 3단계 — 세션 검토 (가장 중요)
자동 익명화는 **카톡 표시 이름**만 확실히 바꾼다. 대화 속 별명, 성 없이 부른 이름, 학교·회사 이름은 놓칠 수 있다.

1. **표시 있는 것만** 필터로 민감·제3자 표시가 붙은 세션부터 본다. 이 세션들은 꺼진 상태로 시작한다.
2. 세션을 눌러 대화를 읽어 보고, 연구에 쓰기 싫은 세션은 체크를 끈다.
3. 바뀌지 않은 이름·장소가 보이면:
   1단계 표의 제3자 이름이나 장소에 추가한다 → 2단계를 다시 실행한다. 검토 결정은 그대로 유지된다.
4. **저장하고 다음 →** 을 누른다.

### 2-7. 4단계 — 만들기와 DB 저장
1. 설정값은 **기본값 그대로** 두고 **실행**한다.
2. 요약 표를 확인한다.
   - **검색 후보**가 30개 미만이면 경고가 뜬다. 대화를 더 내보내 추가할지 담당자와 상의한다.
3. **DB에 저장**을 누른다. 결과 파일: `outputs/kakao/research.db`

### 2-8. 담당자에게 보내기
1. `outputs/kakao/research.db`를 복사해 이름을 `P0X.db`로 바꾼다 (예: `P02.db`).
2. 담당자가 준 비공개 공유 폴더에 올린다.
3. 아래 파일은 **보내지 않는다.**
   - `data/kakao/` 안의 원본과 표
   - `outputs/kakao_web/prepare_report.md` (원래 이름이 남아 있음)

## 3. 담당자: 합치기

1. 공유 폴더에서 받은 `P0X.db` 파일들을 내려받는다.
2. 화면(`python kakao/kakao_web.py`) 4단계의 **여러 사람 DB 합치기** 카드에 끌어다 놓는다.
   - 표에서 파일마다 참여자 ID와 분할 설정이 맞는지 확인한다.
   - 내 대화도 넣으려면 **내 DB(research.db)도 포함**을 체크한다.
3. **합치기**를 누른다. 결과: `outputs/kakao/merged.db`

명령줄로 할 때:
```powershell
python kakao/kakao_db.py --merge P01.db P02.db P03.db --db outputs/kakao/merged.db
```

### 합칠 때 나오는 메시지

| 메시지 | 뜻 | 할 일 |
| --- | --- | --- |
| 참여자 ID가 이미 합본에 있음 | 같은 ID가 두 번 들어옴 | 같은 사람의 새 버전이면 **같은 참여자는 새 것으로 바꾸기** 체크. 다른 사람이면 ID를 고쳐 다시 만들게 함 |
| ○○ 와 ○○ 에 모두 있음 | 받은 파일끼리 ID가 겹침 | 한 사람이 ID를 잘못 넣은 것. 다시 만들게 함 |
| 설문 문항 내용이 다름 | 같은 문항 번호에 다른 질문 | 문항 목록을 통일한 뒤 다시 |
| 분할 조건이 DB마다 다름 (경고) | seed·비율이 다름 | 해당 팀원에게 기본값으로 4단계를 다시 실행하게 함 |
| 가상 샘플 DB 입니다 (경고) | 연습용 파일이 섞임 | 빼고 다시 (**기존 합본 지우고 새로 만들기** 체크) |
| SQLite DB 가 아님 | 엉뚱한 파일 | 올바른 `research.db`를 다시 받음 |

검사에 하나라도 걸리면 아무것도 들어가지 않으니, 고친 뒤 다시 누르면 된다.

### 합친 뒤 확인
- 결과 표의 참여자별 **검색 후보** 수: 30개 미만이면 조건 D가 어렵다.
- **공유 채팅방** 수: 참여자끼리 서로 나눈 대화가 있으면 잡힌다. 교차 비교할 때 참고한다.
- 받은 날짜를 ID 대응표에 체크한다.

> 팀원이 예전 버전으로 만든 DB는 공유 채팅방을 찾는 데 필요한 정보가 없다. 최신 코드를 받은 뒤 4단계 **DB에 저장**을 한 번 더 눌러 다시 보내 달라고 한다.

## 4. 자주 묻는 것

**Q. 화면이 안 열려요 / 포트 사용 중이라고 나와요.**
이미 켜져 있는 창이 있는지 확인한다. 다른 포트로 띄우려면 `python kakao/kakao_web.py --port 8766`.

**Q. 올린 파일의 형식이 인식되지 않아요.**
카톡에서 "텍스트만" 내보냈는지 확인한다. 그래도 안 되면 파일의 첫 몇 줄 **형식만**(이름·내용은 가린 채로) 담당자에게 알려 준다.

**Q. 본인과 상대가 바뀌어 나와요.**
1단계 표의 **본인 이름**에 내 카톡 표시 이름을 정확히 적고 2단계를 다시 실행한다.

**Q. 처음부터 다시 하고 싶어요.**
2단계에서 **검토 결정 초기화**를 체크하고 실행한다. 대화를 추가했다면 1단계에 파일을 더 올리고 2→3→4단계를 다시 한다.

**Q. DB를 이미 보냈는데 고칠 게 생겼어요.**
고친 뒤 4단계 **DB에 저장**을 다시 누르고 같은 이름(`P0X.db`)으로 다시 보낸다. 담당자는 **같은 참여자는 새 것으로 바꾸기**로 합친다.

**Q. 실수로 데이터를 커밋했어요.**
**push하지 말고** 바로 담당자에게 알린다. 이미 push했다면 저장소 기록에서 지우는 작업이 필요하니 혼자 처리하지 않는다.

## 5. 체크리스트

**팀원**
- [ ] 담당자에게 받은 ID로 참여자 칸을 바꿨다
- [ ] 모든 방에 관계를 적었다
- [ ] 3단계에서 표시 있는 세션을 읽고 포함 여부를 정했다
- [ ] 바뀌지 않은 이름·장소가 없는 것을 확인했다
- [ ] 4단계 설정값을 기본값 그대로 두었다
- [ ] `research.db`를 `P0X.db`로 바꿔 비공개 폴더에 올렸다
- [ ] 원본·`prepare_report.md`는 보내지 않았다
- [ ] `git status`에 데이터 파일이 없다

**담당자**
- [ ] ID 대응표를 비공개 문서에 만들었다
- [ ] 공통 설정값과 마감일을 공지했다
- [ ] 받은 DB를 모두 합쳤고 경고가 없다
- [ ] 참여자별 검색 후보 수를 확인했다
- [ ] `merged.db`는 비공개 위치에만 보관한다
