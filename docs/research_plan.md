# 연구 설계 초안

## 잠정 제목

**한국어→영어 업무 대화 번역에서 문맥에 따른 화행과 모호함의 보존**

영문 작업명: Context-Dependent Speech Acts and Ambiguity Preservation in Korean–English Workplace Translation

## 문제와 핵심 구분

같은 한국어 문장이라도 앞선 대화에 따라 거절, 요청, 사실 설명으로 해석될 수 있다. 번역이 공손하고 유창해도 상대가 받아들이는 행동 의도가 달라지면 의사소통에 실패할 수 있다.

번역의 목표는 원문에 근거가 있는 의미·화행·관계적 어조를 유지하는 것이다. 원문이 완곡하면 완곡함을 유지하고, 원문이 모호하면 번역도 그 가능성을 불필요하게 닫지 않는다. 실제 화자의 마음은 관찰할 수 없으므로, 합성 데이터의 작성 의도만을 실제 정답으로 간주하지 않는다.

예: “그건 조금 어려울 것 같아요.”

- 일정 변경이 불가능하다는 앞선 발언 뒤: 완곡한 거절로 읽힐 수 있다.
- 기술적 난이도를 묻는 대화 뒤: 난이도 또는 실현 가능성에 대한 추정일 수 있다.
- 문맥 없음: 둘 다 가능하다. `I refuse`로 단정하면 거절을 과도하게 명시한다.

관계적 거리감은 공손함, 격식, 친밀감과 구분해 기록한다. 직급·나이만으로 의도를 정하지 않는다. 영어의 규범 역시 단일한 것으로 가정하지 않고 대상 독자의 언어 사용 환경을 기록한다. 초기 목표 환경은 국제 업무에서 사용하는 영어 텍스트 대화다.

## 선행연구와 연구 기여 후보

공손함·친밀감·격식 보존은 RASTA(ACL 2025)가 이미 다룬다. 한국어 화용 이해, 한국어 높임 표현의 문맥 번역, 화용적 명시화도 선행연구가 있다. 따라서 “최초의 문화/공손함 번역”을 주장하지 않는다. 자세한 출처와 확인 범위는 `related_work.md`를 참고한다.

이번에 검증할 기여 후보는 다음 세 가지다. 아직 신규성이 확정된 주장은 아니다.

1. **문맥 대조 평가:** 원문을 고정하고 앞선 대화 또는 관계 정보 하나를 바꿔, 번역이 적절하게 달라지거나 유지되는지 평가한다.
2. **모호함 보존 평가:** 정보가 부족할 때 단일 의도를 확정하거나 원문보다 단정적인 말을 추가하는 오류를 측정한다.
3. **수신자 해석 평가:** 번역에 대한 선호뿐 아니라 수신자가 무엇을 요청·거절·약속한 것으로 이해하는지 측정한다.

## 연구 질문과 반증 가능한 가설

RQ1. 문맥을 제공하면 같은 문장의 화행을 더 잘 보존하는가?

- H1: 문맥 제공 조건 B1이 원문만 제공하는 B0보다 명확한 문맥 사례의 화행 보존에서 높다.
- 관계 정보만 바꾸는 사례와 대화 내용만 바꾸는 사례를 구분한다. 두 요소를 함께 바꾼 사례는 자연스러운 상황 대조이며 인과적 효과로 해석하지 않는다.

RQ2. 화용 보존 지침을 추가하면 일반적인 문맥 번역보다 나은가?

- H2: P1이 같은 문맥을 보는 B1보다 수신자 해석을 잘 보존하며, 내용 추가·유창성·내용 충실도에서 손실을 만들지 않는다.
- 단순히 공손하게 하라는 B2 조건, 예시 기반 조건, 가능하면 RASTA 재현 또는 명시적으로 구분한 RASTA 유사 조건을 후속 비교에 추가한다. B0/B1/P1만으로 기존 방법보다 우수하다고 주장하지 않는다.

RQ3. 모호한 원문에서 의도 보존 지침이 과도한 확신을 유발하는가?

- H3: 모호함 보존 지침을 포함한 P1은 이를 뺀 동일 프롬프트보다 부당한 단정과 새 약속을 적게 만든다. 이 절제 실험은 파일럿 후 추가한다.
- 모호한 사례를 명확한 화행 정확도 계산에 강제로 넣지 않는다. 해석의 복수 가능성과 과도한 명시화를 별도로 평가한다.

효과가 없으면 그 결과를 기록한다. B1이 충분히 잘하면 복잡한 시스템 추가보다 실패 유형과 평가 기여를 우선한다.

## 초기 범위

- 언어: 한국어→영어. 사용자 답변에 따라 수정.
- 매체: 텍스트 기반 업무 메신저. 음성·표정·문학·비꼼은 첫 단계에서 제외.
- 기능: 완곡한 거절, 간접 요청, 사실 설명/질문, 수락/사양, 유보, 관계적 어조.
- 입력: 번역 대상 발화, 공개된 앞선 대화 0~3턴, 명시적으로 주어진 관계 정보, 목표 독자 환경.
- 출력: 영어 번역문 한 개. 설명과 해석 후보는 연구용 별도 기록으로 분리한다. 대괄호 해설로 모호함 평가를 우회하지 않는다.
- 학습: 첫 단계는 모델 재학습 없이 동일 모델의 조건 비교. GPU 보유를 전제하지 않는다.

## 데이터와 분리

현재 파일럿: [한국어→영어 파일럿 데이터](../data/pilot_ko_en.jsonl) 24개 / 8개 그룹. AI 작성, 검증 전. `content_context`, `relationship`, `sufficiency` 대조를 구분한다. 같은 그룹이 항상 다른 번역을 요구하는 것은 아니다. 충분히 포괄적인 번역은 두 문맥에서 모두 적절할 수 있다.

1. 파일럿 24개로 한국어 원문 해석과 주석 가이드를 먼저 검토한다.
2. 기준이 안정되면 20~30개 새 그룹으로 예비 실험한다. 개선 폭·분산·평가자 불일치를 관찰한다.
3. 본 실험 후보 규모는 100~150개 그룹, 각 2~3개 문맥이다. 예산과 예비 분산을 바탕으로 최종 표본 수를 정한다. 현재 확정된 표본 수나 검정력 계산은 없다.
4. 그룹 단위로 개발/평가를 나눈다. 표면 표현의 바꿔쓰기, 같은 템플릿과 원 대화, 유사한 시나리오도 같은 분할에 둔다. 파일럿 전체는 개발용으로만 둔다.
5. 새 평가 사례는 개발 프롬프트에 넣지 않는다. 명시/간접 표현, 모호함, 친밀도, 요청 부담 정도를 균형 있게 구성한다.
6. 초기에는 작성된 시나리오로 시작한다. 후속 실제 대화를 쓸 경우 제공자 동의·비식별화·사용 허용 범위를 확인하고 합성/실제 출처를 구분한다.

정답 번역 하나로 고정하지 않는다. 가능한 원문 해석, 내용상 불변 요소, 근거 없는 추가, 허용 번역의 예를 기록한다. 의도 라벨과 참고 번역은 모델 입력에서 제외한다.

## 비교 실험

| 조건 | 모델에 주는 정보 | 목적 |
|---|---|---|
| B0 | 원문과 언어 방향·독자 환경 | 문맥 없는 기준선 |
| B1 | B0 + 앞선 대화 + 관계 정보 | 문맥 제공의 효과 |
| P1 | B1 + 화행·거리감·모호함 보존 및 내용 추가 금지 지침 | 단순 지침 개입의 효과 |

같은 모델 버전·추론 설정·출력 길이 제한을 사용하고 실행 시점과 실제 사용량을 기록한다. API가 동일한 설정을 지원하지 않으면 차이를 명시한다. 고정한 설정으로 필요한 경우 반복 실행해 변동성을 확인한다. 구체적인 모델·실험 비용은 아직 정하지 않았다. 데이터의 날짜·정답 라벨·참고 번역을 모델 입력에 넣지 않는다.

현재 요청 파일은 사례×방법의 대응 관계를 유지하기 위해 72개 행을 갖지만, 서로 다른 메시지 입력은 56개다. B0는 같은 그룹의 원문이 같아 3개 문맥에 동일한 입력을 사용한다. 결정적 실행 결과를 재사용할 경우 이 대응 관계를 보관하고, 확률적 반복 실행을 할 경우 반복이라는 점을 기록한다. 같은 입력의 중복이나 같은 그룹의 문맥을 독립 표본으로 세지 않는다. 이 요청 파일은 모델 실행 지시의 초안이며 평가자에게 직접 보여주는 자료가 아니다.

후속 시스템 후보는 `문맥에서 근거 있는 단서 추출 → 복수 번역 후보 생성 → 내용 추가와 화행 변화 검사 → 선택`이다. 단서 추출은 비공개 사고 과정 수집이 아닌 짧은 구조화된 관찰 항목으로 제한한다. 첫 비교 실험에서 필요성이 확인되면 구현한다.

## 평가

원문 패널은 한국어 모어 화자 3명을 초기 목표로 한다. 목표 언어 패널은 해당 영어 사용 환경에 익숙한 독자 3명을 초기 목표로 하며, 언어 숙련도·경험을 기록한다. 이중언어 평가자는 내용 충실도와 원문 대비 어조를 별도로 검토한다. 인원은 모집과 예산에 따라 조정하되 실제 수를 보고한다.

- 원문 패널: 한국어 원문·문맥만 보고 가능한 화행, 직접성, 공손함, 격식, 거리감, 불확실성을 평가한다. 번역과 초안 라벨을 보지 않는다.
- 영어 패널: 동일한 맥락을 독립 검수한 영어 문맥으로 보고 번역을 해석한다. 원문의 한국어, 초안 정답, 방법명, 다른 조건의 번역을 보지 않는다. 문맥 번역 자체가 화행을 알려주거나 후보 문구를 암시하지 않도록 검수한다.
- 이중언어 패널: 원문과 번역을 보고 내용의 누락·추가 및 화용적 변화의 근거를 기록한다. 방법명은 가린다.
- 사례 순서는 무작위화하고 같은 그룹·다른 방법의 결과를 연속으로 보여주지 않는다. 평가자 배정도 균형화한다. 주석자 불일치는 제거만 하지 말고 분포와 사례로 보고한다.

주요 지표:

1. **명확한 사례의 화행 보존:** 사람 검증으로 해석이 충분히 일치한 사례에서 원문과 번역의 주된 화행이 일치하는 비율. 다중 화행은 별도 다중 라벨 분석.
2. **부당한 단정/추가 비율:** 거절 확정, 새 약속·기한·사과·이유 추가 등 원문과 문맥에 근거가 없는 내용이 포함된 출력 비율. 관습적인 완곡 표현과 사실적 내용 추가를 구분한다.
3. **모호함 보존:** 원문에서 살아 있던 해석이 번역으로 부당하게 배제되는지 이중언어 평가자가 0/1/2로 평정한다. 소수 평가자의 해석 분포 차이는 탐색적으로만 보고한다.
4. **격식·공손함·거리감 보존:** 각 차원의 1~5점 평가와 원문 대비 변화 방향을 기록한다. 서로 다른 언어의 숫자 점수가 직접 동등하다고 가정하지 않고 앵커 사례로 보정한다.
5. **내용 충실도·영어 유창성:** 각각 별도 평가한다. 화행 지표가 좋아도 사실·약속이 바뀐 사례를 성공으로 세지 않는다.

보조 지표로 COMET 계열 또는 표면 유사도 지표를 사용할 수 있지만, 화행 보존의 정답으로 취급하지 않는다. 자동 평가자를 도입하면 별도 사람 주석 자료에서 먼저 타당성을 검증한다. 생성 모델의 자기평가를 핵심 결론의 유일한 근거로 쓰지 않는다.

통계는 그룹 단위 paired bootstrap으로 방법 간 차이의 신뢰구간을 추정하고, 평가자 수와 불일치를 함께 보고한다. 개발 예시 24개로 유의성이나 일반화 성능을 주장하지 않는다. 파일럿 결과를 본 후 본 실험의 주 지표와 분석 기준을 확정·고정한다.

## 진행 순서와 판단 기준

| 단계 | 할 일 | 다음 단계로 넘어가는 근거 |
|---|---|---|
| 1. 범위 확정 | 언어 방향·목표 결과·도메인 결정 | 사용자 요구 반영 |
| 2. 주석 파일럿 | 24개 원문 해석과 예시 번역 검토 | 불일치 원인 파악, 가이드 개정 |
| 3. 예비 비교 | 새 그룹에서 B0/B1/P1 실행 | 실제 실패 사례·평가 비용 확인 |
| 4. 본 실험 설계 | 평가 집합·표본 수·비교법·주 지표 고정 | 프롬프트 개발과 평가 분리 |
| 5. 본 실험 | 독립 사람 평가와 오류 분석 | 개선/무효/역효과 모두 보고 |
| 6. 프로토타입 | 원문·문맥·관계 입력과 번역 결과 화면 | 평가에서 확인한 필요 기능 구현 |

기간은 인력·평가자·예산 확인 전이므로 확정하지 않는다. 초기 산출물은 설계, 데이터 초안, 실행 가능한 요청 생성기이며 아직 번역 서비스나 검증된 벤치마크는 아니다.
